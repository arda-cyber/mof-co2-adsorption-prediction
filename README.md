# MOF CO2 Adsorption Prediction

## About this project

I am a chemistry student building machine learning skills as a complementary
toolkit alongside my primary focus on materials chemistry and, longer-term, deep-tech
entrepreneurship in materials discovery. This project is part of a personal portfolio
aimed at developing genuine understanding of applied ML,
understanding why models work, where their assumptions break, and what their predictions
actually mean physically.

MOFs (Metal-Organic Frameworks) sit at an interesting intersection of chemistry and
physics: their structure is designed through molecular/coordination chemistry, but
properties like gas adsorption are ultimately governed by statistical thermodynamics —
the side of the field I'm more drawn to. CO2 capture using MOFs is a well-studied but
still largely lab-scale application, and one of its real bottlenecks isn't just finding
the material with the highest theoretical capacity, but narrowing an enormous candidate
space (100,000+ hypothetical structures, in databases like the one used here) down to
something worth pursuing further. High-throughput computational screening — the idea
this project is a small-scale exploration of — is one way that gap gets addressed in
practice.

**What this project is:** a supervised regression model that predicts CO2 uptake at a
fixed pressure from structural descriptors (pore size, void fraction, surface area,
metal type), using the hMOF hypothetical MOF database. Along the way, it surfaces a
genuine data quality issue (severe metal-type sampling bias caused by how the database
is organized) and works through fixing it properly, which I think says more about how
I approach a problem than the final model metric does.

**What this project is not:** a claim to explain the full mechanism of CO2 adsorption
in MOFs. The model has no visibility into linker chemistry, functional groups, open
metal sites, or topology — all of which are known to meaningfully affect adsorption
and are deliberately out of scope here. It also doesn't address synthesizability or
long-term material stability, which matter just as much as uptake for anything real
to come out of a screening process like this. I see this project as a first, honest
step into that kind of thinking, not a finished answer.

## Problem framing

**Task type:** Supervised regression. The target (`co2_uptake`) is a continuous
physical quantity, not a category, so this is a regression problem by definition
rather than a modeling choice.

**Target:** CO2 uptake (mol/kg) at 0.5 bar and 298 K.

**Features:** Largest Cavity Diameter (LCD), Pore Limiting Diameter (PLD), void
fraction, gravimetric surface area, and metal type (one-hot encoded).

**Data source:** [MOFX-DB](https://mof.tech.northwestern.edu/), accessed via the
`mofdb_client` Python package, using the hMOF (hypothetical MOF) database — ~138,000
structures generated by algorithmically combining MOF building blocks, with
GCMC-simulated adsorption isotherms for each.

---

## Data Collection & Sampling Strategy

This turned out to be the most methodologically interesting part of the project.

An initial naive sample (the first ~2,000 matching records from the API stream) was
found to be **100% Zn-based**. A second attempt using systematic interval sampling
(every 69th matching record) produced the identical result. Rather than assume this
reflected the true database composition, a full scan of the ~128,000 records matching
the void fraction filter was run to check — confirming the database is organized in
large, contiguous ID-based blocks by metal type, and revealing the true population:

| Metal | Count |
|---|---|
| Zn | 81,090 |
| Cu | 33,128 |
| V | 6,634 |
| Zr | 4,838 |

This is also consistent with the literature: hMOF is built from only 5 inorganic
building-block nodes in total, so limited metal diversity is a known characteristic
of the database, not a sampling artifact.

**Solution:** reservoir sampling in a single pass over the filtered API stream,
maintaining a balanced, randomly-sampled subset of 500 MOFs per metal (2,000 total),
extracting the CO2 uptake at 0.5 bar in the same pass to avoid a much slower
per-MOF re-query step. The resulting dataset is saved as `mof_co2_dataset.csv` to
ensure reproducibility, since the `mofdb-client` API stream order is not guaranteed
to be fully deterministic across requests.

## Exploratory Data Analysis

- **Target distribution:** right-skewed; a `log1p` transform produces a much more
  symmetric distribution, so the model is trained on `log1p(co2_uptake_0.5bar)`.
- **Data quality:** 18/2000 rows (0.9%) had `surface_area_m2g == 0` — physically
  implausible outliers, dropped before modeling.
- **CO2 uptake by metal:** mild differences between metals (V highest mean, Cu
  lowest), but within-group standard deviation (~1.0–1.5 mol/kg) far exceeds the
  between-group spread (~0.3–0.4 mol/kg) — an early signal that metal identity alone
  is a weak predictor, later confirmed by feature importance.
- **Feature correlations:** `lcd` and `pld` are almost perfectly correlated (r = 0.97).
  All structural descriptors are *negatively* correlated with uptake at 0.5 bar —
  consistent with pore-filling behavior dominating at lower pressures (smaller,
  tighter pores → stronger confinement and adsorption potential), while larger-pore
  MOFs express their capacity advantage more clearly at higher pressures.

## Modeling

**Algorithm:** Random Forest Regressor (consistent with prior portfolio projects).

**Baseline result:** a first, unconstrained model showed clear overfitting
(train R² = 0.92 vs. test R² = 0.55 on a single split). A dummy (mean-prediction)
baseline scored R² ≈ -0.05, confirming the model was learning real signal, just not
generalizing well.

**Regularization and validation:** single train/test splits proved noisy (R² varied
from 0.41 to 0.55 across reruns and configurations), so **5-fold cross-validation**
was used going forward as the primary evaluation method. Across several
`max_depth`/`min_samples_leaf` configurations, mean CV R² converged to **0.49–0.53**,
with differences between configurations falling within one standard deviation of each
other — i.e., not statistically meaningful.

**Was the ceiling about data quantity?** A learning curve (5-fold CV across training
set sizes from 130 to ~1,300 samples) showed validation R² rising from 0.38 to ~0.52,
but flattening substantially over the last third of the curve — more data brings
diminishing returns rather than a path to a much higher score.

**Was the ceiling about feature selection?** A systematic comparison of 6 feature-set
variants (dropping `pore_constriction`, dropping metal dummies, dropping `lcd` or
`pld` individually, geometry-only) showed all variants within the same 0.515–0.530
band — no combination of the *existing* features meaningfully changes the outcome.

**Conclusion:** the ~0.52 R² ceiling reflects the information content of the feature
set itself (geometry + coarse metal identity), not a fixable modeling or data-volume
issue.

### Feature importance

| Feature | Importance |
|---|---|
| `surface_area_m2g` | 0.436 |
| `void_fraction` | 0.293 |
| `pld` | 0.123 |
| `lcd` | 0.077 |
| `pore_constriction` (engineered) | 0.027 |
| `metal_Cu` | 0.014 |
| `metal_V` | 0.013 |
| `metal_Zn` | 0.009 |
| `metal_Zr` | 0.007 |

Surface area and void fraction together account for ~73% of the model's predictive
power. Metal identity — despite chemical intuition suggesting it should matter —
contributes under 5% combined, confirming the EDA signal. The engineered
`pore_constriction` feature (lcd − pld) added no measurable value over the raw
`lcd`/`pld` pair.

Interestingly, `pld` outweighs `lcd` by roughly 1.6x, which is chemically sensible:
PLD (the narrowest constriction in the pore network) determines whether gas can
access the pore network at all, while LCD only describes the size of the largest
cavity — accessibility plausibly matters more than raw cavity size at this pressure.

### Performance across the isotherm (multi-output regression)

Rather than only predicting uptake at 0.5 bar, a multi-output Random Forest was
trained to predict uptake at all 5 measured pressure points simultaneously
(0.01–2.5 bar), reusing the same 2,000 MOFs already analyzed.

| Pressure (bar) | Test R² |
|---|---|
| 0.01 | 0.328 |
| 0.05 | 0.358 |
| 0.1 | 0.378 |
| 0.5 | 0.426 |
| 2.5 | 0.545 |

Model R² increases monotonically with pressure. This is consistent with the physical
picture that low-pressure adsorption is governed by adsorbate–surface interaction
strength — sensitive to metal chemistry and functional groups not captured in this
feature set — while high-pressure adsorption approaches saturation and is better
explained by raw geometric capacity (pore volume, surface area), which is exactly
what this model has access to. Predicting all 5 targets jointly did not improve
0.5 bar performance over the single-target model, so the pressure-dependent trend
appears to be a property of the feature set rather than something multi-output
learning alone can fix.

### Where the model fails (residual analysis)

The largest prediction errors are systematic **underpredictions** for geometrically
strong MOFs (above-average surface area and void fraction) whose actual CO2 uptake
exceeds what their geometry alone would predict. This effect is most pronounced for
V- and Zn-based structures (mean absolute error ≈ 0.80 and 0.76 mol/kg respectively)
and weakest for Zr (≈ 0.50 mol/kg) — consistent with Zr's known coordination
stability in MOF chemistry (e.g., the UiO-66 family) versus the more variable
oxidation-state chemistry of vanadium. This points to metal-specific
electronic/coordination effects, not captured by geometric descriptors alone, as a
likely source of the model's remaining error.

## Limitations

- **Feature scope:** no visibility into linker chemistry, functional groups
  (e.g., amine groups known to strongly enhance CO2 affinity), open metal sites, or
  network topology — all established contributors to CO2 adsorption in the
  literature.
- **Hypothetical structures:** hMOF is a computationally generated database; none of
  these structures are guaranteed synthesizable. An attempt to test generalization on
  CoRE MOF 2019 (real, experimentally derived structures) was not completed — the
  measured isotherms in that database don't share hMOF's fixed 5-point pressure grid,
  and a direct-match extraction returned no data at 0.5 bar. This remains open for
  future work (see below).
- **Metal diversity:** limited to the 4 metals present in hMOF (Zn, Cu, V, Zr) —
  far narrower than the real MOF chemical space.
- **Single pressure focus (primary model):** the main model targets 0.5 bar
  specifically; the multi-output analysis shows performance is meaningfully different
  at other points on the isotherm.

---

## Future work (v2)

- Extract additional structural/chemical descriptors directly from CIF files using
  `pymatgen`, to test whether richer geometric or electronic features can move past
  the ~0.52 R² ceiling identified here.
- Revisit generalization testing on CoRE MOF (real, experimental structures) using
  interpolation across each MOF's actual measured pressure points rather than an
  exact-match extraction.
- Reframe as a classification problem (e.g., "exceeds a practical uptake threshold")
  given the primary intended use case (high-throughput screening), which may be more
  robust to the missing chemical features than exact-value regression.
- Deploy the model as an interactive Streamlit app for exploring predictions across
  the feature space.
